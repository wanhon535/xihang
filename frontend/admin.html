DingTalk Roster & Wiki

人员同步

用同一个钉钉企业内部应用只读同步两类数据：通讯录花名册（建号/禁用）和知识库文档列表（只读+跳转）。都不会回写钉钉。

下面三项都留空的话，默认直接复用「安全策略」里钉钉登录用的同一个应用凭证（.env 的 DINGTALK_CLIENT_ID/SECRET + DINGTALK_CORP_ID），不需要重新建应用——只要在钉钉开放平台给这个应用加上「通讯录管理只读」「知识库读权限」「知识库节点读权限」即可。只有想用单独一个应用做同步时才需要填下面几项。

知识库的读取范围取决于「操作人」这个人在钉钉里能看到哪些知识库，不是全公司无差别拉取，这一项没有默认值，必须填。密钥留空提交表示不修改已保存的值。

DingTalk Approval · 建设中

审批流程配置

成本台账里涉及付款的记录，计划提交到钉钉审批后再确认付款。这里预留给后续开发接入：审批模板 processCode、金额审批阈值、发起人/审批人映射等配置项，复用「人员同步」里已经打通的钉钉企业内部应用 AppKey/AppSecret（backend/src/dingtalk-api.js 的 access_token 逻辑），不需要新建钉钉应用。

该功能尚未接入 需要先在钉钉开放平台为现有应用开通「审批」权限并建好审批模板，拿到 processCode 后再回来配置。

Xigou Supervisor Agent · 建设中

智能监督 Agent

汐构监督agent（scripts/xigou-supervisor-brief.mjs）已经能从项目管理模块读取数据、生成停滞/临近节点简报，并真实对接钉钉工作通知和短信预警接口；但目前只能手动执行 npm run report:xigou -- --send-dingtalk --send-sms，还没有接上定时任务。这里预留给后续开发接入：自动调度、最近简报展示、发送记录等。

该功能尚未接入 脚本本身可用，缺的是定时调度和这里的可视化展示，接入后无需改动脚本本身的判断逻辑。
