Core capabilities

四项核心能力，覆盖日常办公主线

不是再堆一套系统，而是给已有的系统加一层入口、一层数据、一层权限。

统一应用入口与 SSO

一次登录，直达全部业务系统

解决「系统在哪、账号是什么」这类每天被问几十遍的问题。把各后台按岗位与业务线登记名称、地址、说明和可见范围，成员登录后看到的就是属于自己岗位的系统清单，点一下直接跳转；凭证放在星钥库集中托管，按权限取用。

钉钉审批同步

不换流程，也能看清每一单

解决「这个单子批到哪了」只能挨个问的问题。申请中心把钉钉审批流同步过来，按类型、状态、申请人、时间归集：发起人看得到进度和卡住的节点，管理者看得到积压。员工仍然在钉钉里提交审批，不需要学新流程。

项目成本台账

全员记账，按项目看清钱花在哪

解决成本分散在多份 Excel、月底靠人肉合并的问题。成员在对应项目下登记支出，发票或支付截图随手挂成凭证，一条记录可挂多张；台账按项目、分类、时间自动汇总，月底不用再拼表，每一笔支出都能对回凭证。

企业知识库

制度、模板、对接文档，全员可查

解决资料跟着人走、新人反复问同一个问题。制度文件、操作手册、对外资料集中存放并按目录组织，全员可检索；权限跟岗位走，人员流动不等于资料流失。与统一入口共用同一套账号，不需要二次开通。

Typical scenes

三个每天都在发生的场景

不谈概念，只看这三件事在汐航 TideSail 里怎么被缩短。

场景一 · IT 负责人

入口和账号，只有 IT 知道

公司有 CRM、财务、工单、监控、云控制台十几个后台，地址和账号只有 IT 知道。同事一问就得停下手里的活去翻记录，人一休假就成了「系统不可用」。

汐航 TideSail 怎么做：系统与凭证集中登记、按岗位分组授权，员工自己就能在入口里找到并跳转。从「问一个人、翻三处记录」变成「一处直达」，IT 也不必再当人工索引。

场景二 · 行政 / 财务

审批与台账，月底两头核对

审批在钉钉里、支出在几个 Excel 里、凭证在聊天记录和手机相册里。月底对账要先导出、再比对、再逐条找票，一次核对耗掉好几天。

汐航 TideSail 怎么做：申请中心把审批按状态归集，成本台账按项目归集支出并把凭证绑在记录上。审批看一处、账看一处，从「多处查找 + 人工比对」变成「同一入口下逐条对应」。

场景三 · 新员工

新人的第一周都在问「文档在哪」

制度、流程、模板散在老员工的电脑和聊天记录里，新人要么反复打扰同事，要么按过期版本办事，出错后才知道规则已经改了。

汐航 TideSail 怎么做：知识库按目录沉淀制度、模板与对接资料，全员可检索，权限跟岗位走。新人从「挨个问人」变成「自己查到」，老人也不用重复回答同一个问题。

FAQ

选型时最常被问到的几个问题

汐航 TideSail 是什么？

汐航 TideSail 是面向中小企业的企业数字化办公效率中枢，把分散的内部系统、钉钉审批、项目成本台账和企业知识库收进一个入口。它不替换企业已有的业务系统，而是在上层提供统一入口、数据汇总与权限控制。

和传统 OA 系统有什么区别？

传统 OA 以审批表单为中心，汐航以「入口 + 数据汇聚」为中心。已经有一堆独立系统的中小企业，缺的通常不是再一套流程引擎，而是把系统、审批、台账串起来的统一入口。所以汐航不要求企业更换现有系统，也不重做审批流程。

支持钉钉审批同步吗？

支持。申请中心会同步钉钉审批流，按类型、状态、申请人和时间归集，发起人能看到进度，管理者能看到积压。员工仍然在钉钉里提交和审批，不需要改用新流程。

数据安全怎么保障？

汐航按角色控制访问范围，各系统凭证集中托管并按权限取用。系统部署在境内服务器，域名已完成 ICP 备案（滇ICP备2026021477号-1），对外调用需通过带权限范围的 API 令牌并保留调用日志。

适合多大规模的团队，多久能用起来？

20 到 200 人、已经有多个独立系统的中小企业最合适。落地只需三步：登记现有系统并分组、按岗位分配账号与权限、通知成员登录，基础配置通常一个工作日就能完成。
