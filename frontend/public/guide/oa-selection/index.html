中小企业 OA 系统怎么选

一份可以直接照做的评估清单：先判断该不该上 OA，再比较五类产品形态、用 12 个维度打分，最后给出实施顺序、预算测算与七个常见坑。适合 20–200 人企业的 IT、行政与财务负责人。

云南汐构信息技术有限公司 发布于 2026-10-24 约 16 分钟阅读

一、先问：你真的需要一套 OA 吗

OA（Office Automation）这个词覆盖的范围极广，从「一个审批表单」到「整套行政管理系统」都有人叫它 OA。所以在选型之前，必须先把自己的问题翻译成具体的能力需求，否则你比较的其实是不同物种。如果你想先搞清楚该不该上OA、选型该看哪几个维度，见《中小企业 OA 系统选型指南》。

一个简单的判断方法：把团队最近一个月的抱怨写下来，归类到这四类里。

抱怨类型典型原话你需要的其实是
找入口「那个系统在哪儿？」「谁有账号？」统一应用入口 + 权限
看流程「这个单子批到哪了？」「谁卡着？」审批线上化 + 状态视图
对数据「这个月花了多少？」「哪笔没凭证？」台账 / 数据归集
找资料「模板在哪？」「上次怎么处理的？」知识库 / 文档管理

如果四类里只有一类突出，用轻量工具就能解决，不必上整套 OA。如果三类以上同时存在，说明你缺的是一层「汇聚」，这时候再谈 OA 才有意义。

一个反直觉的经验：先上 OA 再梳理流程的企业，返工率远高于先梳理流程再选型的企业。因为流程没想清楚时，你只能靠「系统能不能配」来判断，而几乎所有系统都能配——这正是问题的开始。

二、五类产品形态与各自的取舍

市面上的「OA」大致可以分成五类。没有绝对优劣，只有匹配度。

1. 协同平台原生审批（钉钉 / 企微 / 飞书）

优势：零采购成本、员工已在用、移动端体验好、上手几乎无学习成本。

局限：审批类型一多就难检索；跨应用的数据统计弱；系统入口、凭证、台账这类「汇聚」能力不是它的设计目标；深度定制受平台限制。

适合：审批类型少于 10 个、以沟通协同为主的团队。

2. 轻量协同 / 效率中枢

优势：把统一入口、审批汇总、台账、知识库放在一个入口，落地周期短，不替换现有系统。

局限：不做深度行业流程（如制造业工单、医院 HIS），复杂审批链仍需依赖原平台或定制。

适合：已经有一堆独立系统、需要一层入口与汇聚的中小企业。

3. 传统 OA / 协同管理平台

优势：功能完整，公文、用印、会议、档案、流程引擎齐备，支持复杂权限与私有化。

局限：实施周期长、按人天计费、需要专职 IT 维护；中小企业常见结果是功能用了不到三成。

适合：有专职信息化团队、流程复杂、有合规与公文要求的中大型组织。

4. 行业垂直系统

优势：贴合行业流程（工程、医美、教育、物流），字段和报表开箱即用。

局限：跨行业扩展差，容易形成新的孤岛；与通用办公入口的整合往往要额外开发。

适合：核心业务单一、行业流程标准化程度高的企业。

5. 低代码自建

优势：完全贴合自己的流程，改起来快。

局限：「自己搭」意味着「自己维护」：权限、备份、性能、人员交接都是长期成本；业务变化快时容易变成一堆没人敢动的表单。

适合：有稳定开发能力、需求明确且变化可控的团队。

三、12 个维度打分表

把候选产品按下面的维度打分（每项 1–5 分，权重可按你的痛点调整），比「功能列表对比」有效得多，因为功能列表几乎总是全勾。

#维度要看什么建议权重
1入口统一能力能否把现有系统登记、分组、按角色可见、单点跳转高
2审批能力条件分支、会签、超时提醒、与现有审批平台的关系高
3数据归属数据存在哪、能否完整导出、停用后怎么办高
4集成能力是否有开放 API、能否对接钉钉 / 企微 / 自有系统高
5权限颗粒度角色、部门、字段级控制；人员变动时的维护成本中高
6移动端是否支持手机 / 钉钉内打开；外勤场景是否可用中
7实施周期从签约到全员可用需要多久、要不要停机高
8总拥有成本三年总成本（含维护、扩容、内部人力）高
9可扩展性能否加模块、加字段、加流程而不二次开发中
10服务与响应出问题多久响应、有没有本地服务能力中
11迁移成本历史数据能否导入、以后换系统能否带走中
12合规与备案境内是否完成 ICP 备案、数据是否境内存储必要项

第 12 项不是打分项，是门槛项：面向境内客户提供服务且部署在境内的站点应完成 ICP 备案，这一点可以直接在工信部备案系统核对。

四、预算怎么算才不失真

不要比「首年报价」，要比三年总拥有成本（TCO），再折算成人均年成本：

TCO = 软件订阅 / 授权费 + 实施与配置费 + 每年维护与升级费 + 内部投入人力（按人天计）+ 迁移与培训成本 + 因停机或返工造成的业务损失

三个容易漏掉的项：

  • 内部人力。需求梳理、数据准备、培训、答疑都要占人，通常被算成「顺便做一下」。
  • 扩容费。按人数计费的产品，人数从 60 涨到 120 时价格怎么变。
  • 退出成本。停用后数据能不能完整带走。这一条在签约时问清楚，比任何功能都重要。

五、实施顺序：四步走，每步都能独立验收

  1. 统一入口。先让全员有一个登录后就能看到自己系统的工作台。验收：入口周活占比、IT 被问「入口在哪」的次数。
  2. 审批线上化。收敛类型、配好流程、打开状态视图。验收：平均审批时长、退回率、积压单量。详见审批流程线上化方案。
  3. 数据与台账。把支出、凭证、项目归集起来。验收：月底对账耗时、无凭证记录占比。详见项目成本台账怎么记。
  4. 知识沉淀。制度、模板、对接文档集中存放。验收：新人独立完成首个任务的时长。

每一步都应在 2–4 周内看到可量化的变化。如果一步走了两个月还没有指标变化，先停下来复盘需求，而不是继续加模块。

六、七个常见坑

  1. 先选产品后想流程。结果是把混乱自动化，还要为定制付钱。
  2. 只比首年价格。维护费、扩容费、迁移费在第 2–3 年集中出现。
  3. 把「上线」当「成功」。没有使用率指标的 OA 项目，六个月后一定回到 Excel。
  4. 追求功能全覆盖。中小企业通常只需要 20% 的功能，剩下 80% 是采购理由而不是使用理由。
  5. 忽略权限维护成本。权限挂在人身上，一个人离职要改十几处配置。
  6. 没有数据出口。合同里不写导出条款，将来换系统时数据拿不走。
  7. 一次性全员推广。没有灰度就直接铺开，一旦体验有瑕疵，负面口碑会持续很久。

七、汐航 TideSail 在选型中的位置

汐航属于上面第二类——轻量效率中枢，定位很清楚：

  • 做汇聚层，不做替换：统一应用入口把已有系统收进一个工作台，SSO 单点跳转，不要求你放弃现有工具。
  • 审批不重造：申请中心同步钉钉审批流，补上汇总、状态与追溯。
  • 数据落在统一台账：项目成本台账支持全员记账、多凭证留存、按项目汇总。
  • 知识沉淀在组织里：企业知识库全员可用。
  • 可扩展：需要与自有系统对接时，提供带权限范围的 API 令牌与调用日志。
  • 合规：境内服务器部署，域名已完成 ICP 备案（滇ICP备2026021477号-1）。

如果你的需求是公文、用印、人事档案全流程，且团队规模在数百人以上，传统 OA 更合适；汐航不假装能覆盖那部分。

20 人的小公司需要 OA 系统吗？

20 人以下通常不需要独立 OA。钉钉或企业微信原生审批加上一个统一的入口页就够用。真正需要独立系统的时间点通常是：审批类型超过 10 个、出现跨部门统计需求、或者有多个后台系统需要统一入口和权限。

OA 系统一般多少钱？

价格取决于人数、部署方式和定制量三个变量，跨度可以从每年几千元到一次性数十万元，没有可比的单一数字。建议用「总拥有成本」比较：软件费用 + 实施费 + 每年维护费 + 内部投入的人力时间 + 迁移成本，按三年折算成人均年成本再对比。

SaaS 和私有化部署怎么选？

如果没有强制性的数据本地化要求、也没有专职运维，SaaS 的成本与迭代速度明显更优；如果涉及敏感数据、需要与内网系统深度集成、或有行业合规要求，才考虑私有化部署。国内 SaaS 需确认是否完成 ICP 备案、数据是否存放在境内。

已经用了钉钉，还需要买 OA 吗？

钉钉解决的是沟通与基础审批。当你需要把多个后台系统统一到一个入口、需要按岗位控制可见范围、需要把审批与成本台账关联、需要沉淀企业知识库时，缺的是「汇聚层」，可以选择轻量的效率中枢而不是整套 OA。

OA 选型最容易踩的坑是什么？

三个高频坑：一是先选产品后想流程，导致上线后大量定制；二是只比首年报价，忽略维护费、扩容费和迁移成本；三是没有定义验收指标，项目以「系统上线」而非「员工在用」为结束标志。

八、把这份指南变成一次决策

建议的动作：把上面的 12 个维度复制成一张表，给 2–3 个候选产品打分，再用一个 10 人部门试用两周。两周后你会有三个数字，它们比任何演示都可靠。
